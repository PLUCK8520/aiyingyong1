**对照实验（14 题）** —— 这是"贵在哪、值不值"的证据

| 方案 | token/次 | 引用率 | 大纲覆盖度 |
|---|---|---|---|
| B1 裸 LLM 直答 | 127 | N/A | N/A（无大纲，不适用） |
| B2 单轮 RAG（不审计） | 1,566 | N/A | 100% |
| B3 单轮 RAG + 引用审计 | 1,566 | 19.1% | 100% |
| **主系统**（审计 + Reflect + 矛盾检测 + 扇出） | **16,594** | **42.6%** | **100%** |

结论：三层机制让成本约 **130×**，但把引用密度从 19.1% 提到 42.6%（planner 扇出是主因）。

## 五、v1.0 期间修掉的真实缺陷（有实测证据）

| # | 缺陷 | 怎么发现的 |
|---|---|---|
| 1 | 矛盾检测取数取"量级最大"→ 漏报（F1/F3/D1） | 评测硬闸红 → 改取正文第一个数值，实测 2.90×/1.73×/1.94× 触发 |
| 2 | 同一冲突被重复报 3 次（引用编号不同） | 去重键含 topic 与编号 → 只留规范化原话 |
| 3 | **引用悬浮卡与右栏高亮全废**（P6 起就存在） | 浏览器实测：`known` 恒 false（前端剥了括号、后端键带括号） |
| 4 | 连发第二发时误报"取报告失败" | 后端日志 409 Conflict 坐实：前端状态机抢跑 + 成功路径不清错 |
| 5 | `NumpyVectorStore` 未实现协议里的 `dump()` | 研究闭环冷启动恢复时暴露 |
| 6 | 本地 `.env` 会让一批测试**在本机静默失效** | 新增测试"缺 key 应报错"却没报错 → conftest 摘掉 env_file |
| 7 | 厂商不提供 embedding 时整个应用起不来 | 接入 Kimi（无 embedding 接口）时暴露 → 改为降级 + 说明 |
