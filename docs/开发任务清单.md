## P3 · 深检索与反思（约 4 天）

**目标：补齐模板全部核心能力 + 矛盾检测差异化。**

- [x] T3.1 `scripts/ingest_local.py`：md/pdf/txt（pdf 解析用 pypdf，纯 Python 对 3.13 最稳）→ 语义分块 → embedding → Chroma docs collection（统一 VectorStore 接口，预留 Milvus Standalone 切换）；collection 元数据记录 embedder 标识与维度——**切换 embedding 模型必须全量重建索引**，两套向量空间不可混用
  ⚠️ **Chroma 三个静默坑**：①必须显式 `embedding_function=None` 并自传 DashScope 向量，否则首次调用会静默下载约 200MB onnxruntime 模型（无进度提示，像卡死）；②`PersistentClient` 不支持多进程并发（SQLite 文件锁），P6 侧必须单例 client，否则并发写可能损坏数据；③设 `ANONYMIZED_TELEMETRY=False` 关闭默认外发。**单条 chunk 上限 4000 token**（受 T3.3 备用 rerank 约束）
- [x] T3.2 混合检索：rank-bm25 + Chroma 向量双路 → RRF 融合；**中文必须先 jieba 分词再建 BM25 索引**（不分词的中文 BM25 近似失效）
- [x] T3.3 Rerank：主选 **qwen3.7-text-rerank**（单条 30,000 token / 请求 120,000，官方标注 recommended）；备用 **qwen3-rerank**——⚠️ 两者 **endpoint 与请求体结构不同**（前者 `/api/v1/services/rerank/text-rerank/text-rerank`；后者 `{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-api/v1/reranks`），且 qwen3-rerank **单条上限仅 4,000 token、超限直接 HTTP 400 不截断**，用它就必须保证 chunk ≤ 4000 token。gte-rerank 已于 2026-05-30 下线，勿用。兜底：本地 bge-reranker-base（CPU）
- [x] T3.4 `scout_local` 节点（LOC 编号，与 WEB 统一编号体系）

- [x] T3.6 `reflect` 节点 + 条件循环（≤2 轮；本期只做"超限即停"简单判断，分级熔断归 P4 T4.3——依赖不倒置）
- [x] T3.7 **矛盾检测**：judge 升级，同子问题证据两两比对（限额对数），输出 conflicts[]

  验收：本地文档被 LOC 引用；构造矛盾信源 → 报告出现分歧章节；missing_gaps 触发第二轮补检
