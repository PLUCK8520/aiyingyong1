## 五、P8 期间修掉的真实缺陷（均有实测证据）

| # | 缺陷 | 怎么发现的 |
|---|---|---|
| 14 | **判别编号丢方括号 ⇒ 一切查询被误判为"证据不足"**（P0） | T8 端到端验收：上传文档**确实被召回**（references 里 36 条 `local://`，其中 18 条来自它），但 `sufficient=false / n_selected=0` → 拒编页。从 `data/checkpoints.sqlite` 取真实数据比对：判别器 56 条的编号写成 `LOC1-1-1`（无括号），证据侧是 `[LOC1-1-1]`，**交集 0，去括号后 56/56 完全吻合** |
| 15 | **零引用 ⇒ 引用契约整体失效，且表现为"看起来干净"** | 同上轮：正文 0 编号 → 审计**没有对象可审** → `total=0 / unsupported=0`，任何读者都会读成"全部通过"；实测该次正文的「财政补贴 / 税收优惠 / 土地出让收益返还」**根本不在上传文档里**，而文档里的「风险提示」反而没被用 |
| 16 | **上传目录与仓库示例语料同目录且在 git 跟踪范围内**（功能自身引入的泄露通道） | 盘点时发现 `ATTEST_LOCAL_DOCS` 默认 = `data/fixtures/local`＝示例语料目录 → 用户上传的私密资料会被 `git add -A` 提交并推送。已加白名单规则（只放行 `local_*.md`） |
| 17 | `.env.example` 有整块重复（`ATTEST_COMPAT_*` 两遍、`ATTEST_MODEL_RERANK` 两遍）且缺 27 个配置项 | 盘点时用 `config.py` 的 alias 全量对账 |

> #14 的教训值得写进答辩稿：**单测全绿不等于链路可用**。T7.10 那批测试把编号写成 `[WEB1-1-1]`
> ——永远带方括号，恰好绕过真实模型的输出形态，于是这个 P0 在 264 条绿色测试下存活了一整轮。
