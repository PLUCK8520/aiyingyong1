## 0. 设计原则（先立规矩，后面所有细节都从这里推导）

| # | 原则 | 为什么 |
|---|---|---|
| D1 | **节点即纯函数**：`node(state) -> dict`，返回状态增量，不直接 `new` 客户端 | NFR-09 可测试性；节点能脱离网络单测 |
| D2 | **外部依赖全部走接口注入**：LLM / 搜索 / Rerank / 向量库都是 Protocol | NFR-05 可复现；FR-09 离线回放 |
| D3 | **并行写入的字段必须声明 reducer** | LangGraph 默认覆盖语义，少了会静默丢数据 |
| D4 | **每个降级动作必须留痕**：写 `errors[]` 或 `fuse_level` | NFR-03、NFR-04；"降级不停机"要能自证 |
| D5 | **报告可以残缺，不可以造假**：证据不足就写"信息不足"，不补空话 | 这是本项目的立身之本（P1/P3） |
| D6 | **成本是一等公民**：任何新增调用都要先回答"它占多少 token" | P4；FR-20/21 |

## 2. 模块职责边界

**"不负责什么"比"负责什么"更重要**——它是防止模块互相污染的唯一约束。

| 模块 | 负责 | **明确不负责** | 输入 → 输出 |
|---|---|---|---|
| `intent_router` | 二分流判定 + 给出理由 | 不做问题改写、不做规划 | `query` → `route`, `route_reason` |
| `direct_responder` | 单轮直答，带缓存 | 不检索、不引用编号 | `query` → `direct_answer` |
| `planner` | 输出目标 / 子问题 / 大纲 | 不检索、不判断可行性 | `query` → `plan` |
| `scout_web` | 生成查询词、调 Tavily、抓正文、登记证据 | **不做相关性判断**（交给 judge）、不做去重之外的筛选 | `sub_question` → `evidence[]` |
| `scout_local` | 双集合（docs / research_memory）混合检索 + rerank | 不做矛盾判断 | `sub_question` → `evidence[]` |
| `evidence_judge` | 相关性 / 置信度 / 缺口 / 矛盾检测 | **不写报告**、不改写证据原文 | `evidence[]` → `judgments[]`, `gaps[]`, `conflicts[]` |
| `reflect` | 判断是否补检、生成补检查询 | 不做熔断决策（只读派生值 `fuse_level` 执行） | `gaps[]`, `cost_incurred` → 下一轮 or 继续 |
| `analyst` | 按大纲分章成文、内联引用 | **不新增事实**、不自行判断引用是否成立 | `plan`, `evidence[]`, `conflicts[]` → `report` |
| `citation_auditor` | 逐句核验引用、输出裁决与降级动作 | 不改证据、不重写全文（只触发章节重写） | `report`, `evidence[]` → `audit_results[]` |
| 预算与熔断 | 累加 `cost_incurred`、由它派生 `fuse_level` | 不决定"哪个模型"（那是路由器的事）；**不持有可变账户对象**（架构设计 ADR-02） | LLM 网关增量 → `cost_incurred` |
| 模型路由器 | 任务类型 → 模型映射 | 不记账 | `task_type`, `fuse_level` → `model` |
| trace writer | 落盘节点事件 | 不参与业务逻辑 | 事件 → `trace.jsonl` |

## 3. 状态设计（LangGraph State）

**这是最容易踩坑的地方**：默认覆盖语义下，并行分支写同一字段会互相覆盖，且**不报错**。

| 字段 | 类型 | Reducer | 写入者 | 备注 |
|---|---|---|---|---|
| `query` | `str` | 覆盖 | 入口 | |
| `route` | `Literal["direct","research"]` | 覆盖 | `intent_router` | |
| `route_reason` | `str` | 覆盖 | `intent_router` | 便于调参与答辩解释 |
| `direct_answer` | `str \| None` | 覆盖 | `direct_responder` | |
| `plan` | `Plan` | 覆盖 | `planner` / 人工确认后 | |
| `plan_approved` | `bool` | 覆盖 | 人工确认节点 | |
| `round` | `int` | 覆盖 | `reflect` | **引用编号的轮次来源** |
| `reflect_count` | `int` | 覆盖 | `reflect` | ≤ 2 |
| `evidence` | `list[Evidence]` | **`operator.add`** | `scout_web` / `scout_local`（并行） | 不加 reducer = 丢证据 |
| `judgments` | `list[JudgeOut]` | **`operator.add`** | `evidence_judge`（并行） | |
| `gaps` | `list[str]` | **`operator.add`** | `evidence_judge` | |
| `conflicts` | `list[Conflict]` | **`operator.add`** | `evidence_judge` | |
| `report` | `Report` | 覆盖 | `analyst` | |
| `audit_results` | `list[AuditOut]` | **`operator.add`** | `citation_auditor` | |
| `rewrite_count` | `int` | 覆盖 | 审计降级动作 | ≤ 1 |
| `cost_incurred` | `Annotated[float, operator.add]` | 累加 | LLM 网关（节点回传增量） | **唯一被并行写入的预算字段**（架构设计 ADR-02） |
| `budget_cfg` | `BudgetConfig` | 覆盖 | 入口 | 静态配置（total / L1 / L2 阈值），不参与并发写 |
| `model_tier` | `Literal["strong","fast"]` | 覆盖 | 模型路由器 | 当前档位，供 trace 与降级判断 |
| `profile` | `Profile` | 覆盖 | 记忆加载节点 | |
| `memory_hits` | `list[MemoryItem]` | **`operator.add`** | `scout_local` | 研究闭环 |
| `errors` | `list[NodeError]` | **`operator.add`** | 所有节点 | 降级留痕 |
| `fuse_level` | `Literal[0,1,2]` | **派生值**（不入 state，由 `f(cost_incurred, budget_cfg)` 计算） | — | 派生可避免"忘记更新"导致的不一致 |

> **验收方式**：写一条单测，构造 3 路并行 Send，断言 `evidence` 长度为 3（而非 1）。这条测试在 P1 就要有（T0.7）。

## 4. 流程设计

### 4.1 主流程

```
入口
 └─ intent_router
     ├─ direct → direct_responder → 输出（跳过全部检索与审计）
     └─ research → planner → [interrupt] 人工确认大纲（可跳过/可编辑）
          → Send 扇出（按 sub_questions）
               ├─ scout_web   ┐
               └─ scout_local ┘ 并行
          → evidence_judge（判相关性 + 缺口 + 矛盾）
          → reflect
               ├─ 有缺口且 reflect_count < 2 且 fuse_level < 2 → round += 1，回到 Send
               └─ 否则 → analyst
          → analyst（按大纲成文，含"争议与分歧"章节）
          → citation_auditor（分组批量核验）
               ├─ 不支撑比例超阈值且 rewrite_count < 1 → 章节重写，回 analyst
               └─ 否则 → 报告后处理（引用完整性校验）
          → 输出报告 → 研究闭环沉淀（仅 supported）
```

### 4.2 降级流程（多数设计文档缺这一块，但它是本项目的核心卖点）

| 触发条件 | 降级动作 | 必须保证 |
|---|---|---|
| `cost_incurred / budget_cfg.total_tokens ≥ 0.70` | 派生 `fuse_level = 1`：轻任务（intent / 摘要 / 审计初筛）切小模型或本地 Ollama | 主链路模型不变，报告质量不受影响 |
| `cost_incurred / budget_cfg.total_tokens ≥ 0.90` | 派生 `fuse_level = 2`：停补检 + 上下文截断（证据按相关性取 top-k）+ 审计只跑初筛 | **报告仍必须产出**，并在报告头标注降级级别 |
| 检索全部失败 | 跳过该子问题，写入 `gaps` | 报告对应章节写"信息不足"，不编内容（D5） |
| 结构化输出校验连续失败 2 次 | 降级为宽松解析 + 保留原文 | 不中断链路 |
| 审计不支撑比例 > 阈值 | 该章节重写 1 次；仍不达标则整段标注"未证实" | 不留"看似有据实则无据"的句子 |
| 进程中断 | 从检查点恢复 | 不重复已完成的检索（避免重复扣额度） |

### 4.3 人机协同流程（FR-04 / FR-24）

```
planner 产出 plan
  → interrupt()：抛出待确认大纲
      ├─ 用户直接 resume（不改）→ 继续
      ├─ 用户改大纲后 Command(resume=edited_plan) → 用新 plan 继续
      └─ 用户选择跳过确认 → 走配置项直接继续
  → 任意节点中止：checkpointer 保留状态，重启后按 thread_id 恢复
```

⚠️ **必须防的坑（2026-09-10 依据 LangChain 官方文档补）**：resume 时**该节点从头重新执行**（官方原文 *"resumes from the start of the node, re-executing all logic"*），所以 `interrupt()` 之前的副作用会重复触发。两条硬性约定：

1. `interrupt()` 必须放在节点**最前面**，其后才是副作用；
2. 副作用前加状态守卫（例：先判 `plan_approved` 已为真则跳过重跑）。**否则"恢复时不重复检索、不重复扣额度"这条验收无法通过。**

另：`Command(update=...)` 不能单独作为 invoke 输入续跑对话（会"卡住"），续跑用 `Command(resume=...)`，开新回合用普通 dict。

## 5. 关键接口契约

**全部为 Protocol，实现类可替换、可在测试中 mock（D2）。**

```python
class LLMGateway(Protocol):
    def chat(self, messages: list[Msg], *, task_type: str, json_schema: type | None = None,
             think: bool = False) -> LLMResult: ...
    def embed(self, texts: list[str], *, dimensions: int) -> list[list[float]]: ...

class LLMResult:            # 思考模型的 reasoning 必须与正文分离（T0.3）
    text: str
    reasoning: str | None   # 不进入上下文、不进入报告
    model: str
    prompt_tokens: int
    completion_tokens: int
    cost: float             # 由 config 单价表算出

class SearchClient(Protocol):
    def search(self, query: str, *, max_results: int, mock: bool = False) -> list[RawDoc]: ...

class Reranker(Protocol):
    def rerank(self, query: str, docs: list[str], *, top_n: int) -> list[tuple[int, float]]: ...

class VectorStore(Protocol):
    def upsert(self, collection: str, items: list[VectorItem]) -> None: ...
    def query(self, collection: str, vector: list[float], *,
              top_k: int, where: dict | None = None) -> list[Hit]: ...

class NodeError:
    node: str
    kind: str               # rate_limit | parse_fail | http_400 | budget | timeout
    detail: str
    degraded: bool          # 是否触发了降级
```

**节点签名统一约定**：

```python
def scout_web(state: GraphState, *, search: SearchClient, citator: Citator) -> dict:
    ...
    return {"evidence": new_evidence, "errors": new_errors}
```

依赖从容器取、不从全局取——这是 D1/D2 的落点，也是"能单测"的前提。

## 6. 关键算法设计

### 6.1 引用编号规则（FR-15）

```
{类型}{轮次}-{子问题}-{序号}
类型   : WEB（网络） | LOC（本地库，含 research_memory 命中）
轮次   : 检索轮次，首轮 = 1，reflect 补检递增，来自 state.round
子问题 : plan.sub_questions 的 1-based 序号
序号   : 该子问题该轮内的证据顺序，从 1 开始

示例：WEB1-2-3 = 第 1 轮检索 / 第 2 个子问题 / 第 3 条网络证据
```

设计约束：
- **编号在证据登记时分配，不在写作时分配**——否则并行分支会撞号。
- 必须维护**反查索引** `citation_id -> Evidence`，供引用悬浮卡与审计使用。
- 重写章节时**编号不回滚**（已发出的编号保持稳定，避免报告前后不一致）。

### 6.2 混合检索与 RRF 融合（FR-06）

```
query
 ├─ BM25（jieba 分词后建索引）→ rank_bm25 结果
 └─ 向量召回（Chroma）→ 相似度结果
      ↓
 RRF 融合：score(d) = Σ_{r ∈ 结果集} 1 / (k + rank_r(d))，k = 60
      ↓
 取 top-N（N ≈ 20–50）→ qwen3.7-text-rerank 精排 → top-k（k ≈ 5–10）
```

约束：
- 中文必须先 jieba 分词，否则 BM25 近似失效（T3.2）。
- 单条 chunk ≤ 4000 token（受备用 rerank 上限约束，T3.3）。
- 融合后按 URL / 内容 hash 去重（FR-08），减少重复 token。

### 6.3 矛盾检测的配对策略（FR-12）

朴素两两比对是 O(n²)，成本不可接受。采用**先聚类再簇内比对**：

```
同子问题证据
 → 按主题做 embedding 聚类（阈值可配）
 → 仅在簇内两两比对
 → 每簇最多 6 对，全局上限 30 对；超出按簇内相似度降序截断
 → 输出 conflicts[{claim_a, source_a, claim_b, source_b, topic, severity}]
```

**成本上限必须写进配置**，否则证据一多就会烧穿预算。

### 6.4 审计的分组批量核验（FR-17）

朴素做法"每句一次调用"，调用数随报告长度线性爆炸。改为**按引用分组**：

```
报告拆句 → 抽出所有带引用的句子
 → 按 citation_id 分组
 → 每组一次调用：证据原文 + 该组全部 claim → 返回每条 claim 的 verdict
 → flash 初筛：高置信直接判 supported；拿不准的交强模型复核
```

调用次数从"句子数"降到"不同引用数"，预计降低 5–10 倍（审查报告 F-2 / 风险表）。

裁决枚举：`supported | unsupported | partial`；动作：`keep | downgrade | rewrite`。

### 6.5 预算熔断（FR-21）

| 级别 | 触发（`r = cost_incurred / budget_cfg.total_tokens`） | 动作 |
|---|---|---|
| 0 | `r < 0.70` | 正常 |
| 1 | `r ≥ 0.70` | 轻任务切小模型 / 本地；主链路不动 |
| 2 | `r ≥ 0.90` | 停补检、截断上下文、审计只跑初筛 |

`fuse_level` 是 `r` 与阈值的**纯函数**——不写入 state、不手动更新，因此不可能出现"忘记更新"的不一致（架构设计 ADR-02）。

**不变式**：任何级别下报告都必须产出。熔断的目的是"降质保交付"，不是"停止服务"。

## 7. 数据设计

| 存储 | 内容 | 关键字段 / 元数据 |
|---|---|---|
| SQLite checkpoint | LangGraph 状态快照 | `thread_id`（CLI 用同步 Saver；FastAPI 用 AsyncSqliteSaver） |
| SQLite profile | 用户偏好 | `key`, `value`, `updated_at` |
| Chroma `docs` | 本地知识库 | `source_path`, `chunk_id`, **`embedder` 标识**, **`dim`** |
| Chroma `research_memory` | 研究闭环沉淀 | `report_id`, `sub_question`, **`audit_verdict`**, `created_at` |
| `trace.jsonl` | 节点事件流 | `ts`, `node`, `event`, `model`, `tokens`, `cost` |
| `data/cache/` | Tavily 响应录制 | 查询 hash → 完整响应（供回放） |

两条硬约束：
1. **切换 embedding 模型必须全量重建索引**，`embedder` + `dim` 写进 collection 元数据（NFR-11）。
2. **只有 `audit_verdict = supported` 的结论允许写入 `research_memory`**（FR-27），否则错误会被后续调研当成"已有知识"复用。

## 8. 前端功能设计

| 区域 | 功能 | 交互态（空 / 加载 / 降级 / 错误） |
|---|---|---|
| 会话侧栏 | 会话列表、新建、切换 thread | 空态给引导文案；会话项显示状态点（运行中/已完成/已中断） |
| 聊天窗 | 提问、流式接收报告 | 运行中显示节点级进度；中断显示"恢复"按钮 |
| 执行时间线 | 节点 start/end/耗时/token | 每节点一行，可展开看 model 与成本 |
| 成本面板 | 累计 token / 成本 / 熔断级别 | 级别 1 黄条、级别 2 红条并提示"已降级，报告可能不完整" |
| 报告双栏 | 左正文右引用 | 引用悬浮卡显示证据原文与来源链接 |
| 大纲确认 | 编辑章节、增删、确认/跳过 | 模态内可改标题与要点；超时未操作给默认继续 |
| 断点恢复 | 从检查点续跑 | 中断会话在侧栏有醒目标记 |

**设计约束**：SSE 断线必须可重连（否则长任务体验崩），这是 B 轨需求里"看得见的工程细节"。

## 9. 失败模式与处理总表

**这张表是本项目最有价值的资产之一**——它同时也是 `docs/cases/` 的采集清单。

| # | 失败模式 | 检测方式 | 处理动作 | 用户可见表现 |
|---|---|---|---|---|
| 1 | Tavily 429 限速 | HTTP 状态码 | 指数退避 + 并发降到 ≤ 3 | 进度显示"检索降速" |
| 2 | 正文超长导致上下文爆炸 | token 计数 | 单条正文截断（默认 4000 字符） | 无感 |
| 3 | Rerank HTTP 400（单条 > 4000 token） | 异常捕获 | 截断后重试一次 | 日志告警，报告无感 |
| 4 | 结构化输出校验失败 | Pydantic 校验 | 重试 ≤ 2 次 → 宽松解析 | 无感（记录 error） |
| 5 | 并行扇出丢证据 | 单测断言（3 路 → 长度 3） | reducer 修正 | 无感 |
| 6 | Chroma 多进程并发冲突 | 异常 / 锁超时 | 单例 client + 重试 | 无感 |
| 7 | 免费额度耗尽 | 调用返回错误码 | 切 Ollama | 报告头标注"本地模型降级" |
| 8 | 预算超限 | 记账比对阈值 | 分级熔断 | 成本面板黄/红条 |
| 9 | 审计判定为不支撑 | 裁决结果 | 标注"未证实"或章节重写 | 句子带标注样式 |
| 10 | 检索全失败 | 证据数 = 0 | 该子问题写入 gaps | 章节显示"信息不足" |
| 11 | 进程中断 | 启动时发现未完成 thread | 从检查点恢复 | 侧栏"恢复"按钮 |
| 12 | 引用编号缺失来源 | 完整性校验 | 阻止输出并报错 | 明确错误提示（而非静默出报告） |
| 13 | **resume 时节点从头重跑，副作用重复触发** | trace 中出现重复的检索事件 | `interrupt()` 置于节点首行 + 状态守卫 | 无感（但不做则重复扣额度） |
| 14 | **单价按单一费率算，长上下文账单偏高** | 记账额与平台账单对不上 | `PRICING` 按"模型 × 上下文档位"二维定价 | 成本面板数字偏低（隐瞒真实花费） |

**规则**：任何一行被真实触发，都要记入 `docs/cases/`（任务清单头部规则）。这张表是"预期"，cases 是"实证"——两者叠加才是面试可用的材料。

## 10. 验收口径

| 功能域 | 怎么算通过 |
|---|---|
| F1 意图与规划 | 20 条标注样本分流准确率 ≥ 90%；改大纲后报告结构随之变化 |
| F2 检索 | 每个子问题 ≥ 2 条有效证据；`mock=True` 全链路离线跑通 |
| F3 证据与反思 | 缺口语料触发第二轮且 ≤ 2 轮；构造矛盾信源 → 输出 conflicts 非空 |
| F4 成文与审计 | 注入 5 条假引用 → 全部识别并降级；引用完整性校验零遗漏 |
| F5 成本治理 | 记账与账单误差 < 5%；预算调小后熔断生效且报告仍产出 |
| F6 记忆与协同 | 强杀进程后恢复且不重复检索；换 thread 偏好仍生效 |
| F7 可观测与评测 | trace 事件成对无孤儿；`python -m eval.mini` 出两指标；完整版出 baseline 对照 |
