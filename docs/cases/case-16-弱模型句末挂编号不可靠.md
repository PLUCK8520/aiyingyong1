# 案例 #16 · 弱模型"句末挂编号"不可靠：把排版动作交给代码

- **标签**：结构化输出 / 指令服从性 / 架构取舍
- **发现**：2026-09-13/14（案例 #15 的延续）；根治于 T9.1
- **状态**：已落地（`llm/prompts.py` 结构化协议四件套 + `analyst` 结构化优先分支）

## 现象

T8.6（案例 #15）修完，报告**不再伪装成"审计通过"**了——但代价是每次都顶着
「本报告未通过逐句回查」横幅。**"把失效标出来"不等于"让引用生成出来"**：
只要模型不写编号，报告就永远是个残次品。

换强模型的路被额度挡住（智谱 air/plus/4.5/4.6 全 429、SiliconFlow 402），
于是问题收敛成一句话：**在只能用 glm-4-flash 免费档的前提下，怎么让它稳定产生引用？**

## 根因（一个被证伪的假设 + 一个被验证的观察）

- 被证伪：提示词里编号**是可见的**（实测 `[LOC1-1-1]`…都在 prompt 内），
  所以不是"看不到编号"；调提示词也已证伪（案例 #15 的 V2 退化）。
- 被验证：glm-4-flash 最不服从事项，恰恰是**"在结论句末精准挂上编号"**这个排版动作；
  而**"把用到的编号从证据块里抄一遍"**——抄写，服从难度低一个量级。

## 修复（T9.1：把编号从"模型的排版动作"改成"代码的确定性拼装"）

模型只负责**按章声明**：`<<CHAPTER>>/<<CITE>>/<<TEXT>>/<<END>>` 分章输出，
每章在 `<<CITE>>` 行列出本章依据的证据编号。代码 `render_structured_report`
把声明确定性注入正文（章末依据行 `（本节论述依据：…）`）。

关键语义边界（防止再造一个"假干净"）：
- 依据行是**章节级元信息**，审计不把它当 claim；
- 但本章**无编号的句子**关联本章声明编号集合**逐句受审**（按所引来源并集核对）——
  否则"有编号但无审计对象"就是案例 #15 的翻版。

**结构化是增强，不是硬依赖**：`parse_structured_report` 解析不出 → 降级回纯文本路径，
T8.6 纠偏逻辑原样保留。

## 验证

- 单次真实档（thread `t91-real-1`，glm-4-flash + mock 检索，5m28s/¥0）：模型**服从格式**，
  报告 7 章全带依据行，`referenced=8 / unresolved=0`，审计 `total=22`
  （supported 3 / partial 10 / unsupported 9 / 降级 7 句），`inconclusive=False`——
  零引用横幅消失，审计第一次对真实档报告有了可审对象，且真的在抓东西
  （证据里没有的"55%/45% 占比"被判 unsupported）。
- 统计样本：见 `scripts/eval_ab_t91.py` 的运行报告（`docs/eval-reports/ab-t91-*.md`，
  A/B 对照 新协议 vs 旧协议，各 6 轮）。

## 教训

1. **别让模型做它天生不擅长的事，更别在它不擅长的事上反复调提示词**。
   编号"生成"（判断用哪条证据）是模型的活；编号"排版"（挂在句末）是代码的活。
   把二者拆开，各归各的确定性边界。
2. **降级路径是结构化方案的保命设计**。模型不服从格式不能变成新的事故——
   所以"解析失败→纯文本+纠偏"这条旧路必须原样保留，结构化只是走得更前面一步。
3. **审计语义要和注入方式配套改**。注入编号只是第一步，如果审计不知道"依据行是元信息、
   章节句子要关联声明编号"，就会要么把依据行误杀、要么又退回"无对象可审"。
