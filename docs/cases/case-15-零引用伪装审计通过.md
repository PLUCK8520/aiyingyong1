# 案例 #15 · 零引用伪装成"审计通过"

- **标签**：P0 / 引用契约整体失效 / 审计语义
- **发现**：2026-09-13 真实档端到端（glm-4-flash，thread `kb-e2e-3`）
- **状态**：已修复（T8.6：有界纠偏 + 确定性兜底横幅 + `no_citations`/`inconclusive` 字段）

## 现象

`sufficient=true`、5 条证据全部通过判据、正文内容逐条对得上上传文档——但**正文一个引用
编号都没写**（`citation_check.referenced=0`）。与此同时报告第五节凭空生成了
「财政补贴 / 税收优惠 / 土地出让收益返还」，而这几项**根本不在上传文档里**（已拿原文逐条核对）。

最要命的是：审计器**没有对象可审**，`audit_summary` 报出 `total=0 / unsupported=0 /
unsupported_ratio=0.0`——**任何读者都会读成"全部通过"**。

## 根因

引用审计的入口是"正文里带编号的句子"。正文没有编号 ⇒ 没有句子被抽出来审 ⇒
审计"没发现任何问题"。而这个"0 条问题"被 UI 和摘要原样呈现为"干净"。

**引用缺失会让整张核验网失效，且失效的表现是"看起来干净"。** 凭空内容（财政补贴等）
反而比"引错编号"更安全地混过去——引错会被 `unresolved` 抓住，不引则整张网直接短路。

## 怎么发现的

端到端验收时不是看"有没有报错"，而是拿上传文档原文**逐条对**报告正文，
发现第五节的内容文档里根本没有，才反查到"引用是 0"。

## 修复（T8.6，三层，缺一层都还是自欺）

1. **有界纠偏**：首轮零编号且确有证据时，把硬约束追加到**最后一条 user 消息末尾**重试一次；
   两次都失败即停（继续烧调用换不来服从度）。两轮成本合并记账。
2. **确定性兜底**（不依赖模型）：报告一级标题后插「⚠️ 本报告未通过逐句回查」横幅；
   `citation_check.no_citations` 字段；`audit_summary.inconclusive` + 原因文案。
   → **"审计没有结论"必须能与"审计通过"区分开**。
3. 横幅判定基于**降级前**的正文（先切掉参考资料章节），否则"引了但被降级"会被误读成"没引"。

## 教训

1. **计数为 0 的字段天然携带歧义**："0 个问题"既可能是"全对"也可能是"没查"。
   凡是"无对象可审"这类状态，必须用显式字段命名（`no_citations`/`inconclusive`），
   不能靠读者从一串 0 里猜。
2. **提示词调优这条路被证伪**：同一证据、同一温度的三变体实验（V0 原文→0 编号；
   V1 末尾加自检句→1 编号；V2 = V1 + 显式编号清单→**退回 0**）——加了约束反而退化，
   说明 glm-4-flash 的服从性不稳定，**不能靠调提示词宣称修好**。
3. 根治要靠**换更强的模型**或**改输出协议**（后一条即 T9.1 / 案例 #16）。
