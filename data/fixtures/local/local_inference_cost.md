# 内部笔记：大模型推理成本的三个常见误读（2025H1）

## 误读一：把「单价降幅」当成本结论

本笔记跟踪的是**输入侧单 token 单价**，2024–2025 年降幅约 78%。
但如果按**调用量加权**，平均降幅只有约 45%——
因为长上下文与推理型任务的用量占比在上升，而它们的单价降幅最小。
**报「降了 78%」还是「降了 45%」，取决于口径**，两个数都对，但必须写明。

## 误读二：单价降了 ≠ 账单降了

单价大幅下降的同时，企业内部**推理总支出**同期上升约 60%。
原因是任务复杂度提升（多步 Agent 编排、长链推理）抵消了单价下降。
把单价趋势直接当成总成本趋势，是本领域最高频的误读。

## 误读三：自建一定更便宜

按内部测算，GPU 利用率低于约 30% 时，调用 API 更便宜；高于 60% 自建才有优势。
（注：此处的 30% / 60% 是**内部测算阈值**，与外部报道引用的数字口径不同，
不要混用。）实际观测到的企业利用率多在 15%–25%，因此「自建省钱」在中小规模下通常不成立。

## 附：降本手段的收益区间（本笔记口径）

| 手段 | 收益区间 | 代价 |
|---|---|---|
| 提示词缓存 | 20%–60% | 依赖请求重复度 |
| 模型路由 | 30%–70% | 需评估质量损失 |
| 输出长度控制 | 10%–25% | 可实现性最好 |
| 量化推理 | 约 40% | 首 token 延迟 +15%–30% |
